# 16 术语表

本表按本白皮书语境解释主要术语。相同词语在产品使用与经济机制中可能涉及不同对象，阅读时应结合对应章节。例如，项目中的“服务结算”承接模型、工具和市场交易，收益型机制中的“收益核算”则承接入金基准、奖励与出局条件。

| 术语 | 本文含义 |
| --- | --- |
| Orange Personal Cloud | OPC 个人云产品，承接项目资料、执行环境、任务、版本和发布，使应用能够持续迭代与经营。 |
| OPC 代币 | 本模型发行和奖励发放使用的代币，总量 130,000,000 枚。应与同名产品简称结合语境区分。 |
| SIGN | AI 服务与生态协作的底层结算代币；同时在收益型入金中充当中间交换，并与 OPC 形成流动性配对。 |
| OPI | OPC 的橙色 AI 小机长品牌形象，用于产品引导、社群内容与品牌传播。 |
| 个人云 | 保存项目资料、文件、执行与版本、任务进度和发布的工作环境，由手机与电脑等入口连接。 |
| 工作台 | 连接项目工作的控制台；通过 API 读取获授权的业务群中的讨论背景，将相关需求与反馈带入项目。 |
| 业务背景／项目背景 | 与工作有关的需求、业务背景、已有资料、产物和验收要求，为后续任务提供理解基础。 |
| 智能体 | 围绕具体任务执行工作的 AI 能力。多个智能体可以共享项目背景、按任务关系并发协作。 |
| 并发 | 在依赖条件允许时，同时推进能够独立执行的工作，再将结果衔接至后续任务。 |
| 工作树 | 保存某项任务更改的独立工作空间，为并行修改、审阅和整合提供边界。 |
| 版本 | 一轮更改整合后的项目状态，承接本轮产物与发布，也为下一轮工作提供起点。 |
| 发布 | 把确认后的应用版本发布出去；OPC 的默认路径为发布到个人云。 |
| 版本发布 | 新版本及其对应更改说明，可进一步准备文案与海报，经确认后向外发布。 |
| 应用市场 | OPC 的任务与能力市场，连接需求发布、创作者接单、智能体交付，以及应用、智能体、模板上架。 |
| 服务记录 | 项目中模型与工具调用、智能体执行及市场交易等记录，接入底层服务结算。 |
| 矿池 | 收益型机制中的矿池，涉及 OPC 分配、LP 持有、奖励库存与相关发放安排。 |
| LP | 流动性配对形成的份额。初始 OPC/SIGN LP 进入矿池，后续入金按规则继续形成 LP。 |
| 即时 LP | 收益型入金价值的 20%，其中 10% 买入 OPC，10% 对应 SIGN 与其配对。 |
| 递延 LP | 收益型入金价值的 70%，在十天内按安排添加；当日资金一半买 OPC、一半以 SIGN 配对。 |
| 奖励库存 | 本模型中用于奖励安排的 OPC 库存，LP 赎回后的资产转换是其来源路径之一。 |
| 静态奖励 | 本金 USDT×当期公示日率形成应计 USDT，再按当期公示 OPC 换算价支付。日率区间为 0.5%—1%。 |
| 动态预算 | 本次静态奖励 OPC 数量×50%形成额外预算，再以这笔动态预算为基数，按直推10%、代数20%、级差60%、平级10%分类，未分配留矿池。 |
| USDT 本位 | 使用入金 USDT 作为相关收益和出局的核算基准，SIGN 价格上涨不改变这一基准。 |
| 出局 | 达到相应条件后终止收益资格的机制状态，包括累计收益达到 2.5 倍及提前赎回后出局。 |
| 提前赎回 | 累计收益≤本金 50% 时，按规则取回本金 70% 后出局；超过 50% 不可按该条件赎回。 |

术语与具体工作相互对应：项目背景帮助理解需求，工作树保留更改，版本承接交付，服务记录连接 SIGN 结算。矿池参与则沿本金、奖励和出局继续核对，完整运行方式见[第十七章：机制运行与结算细则](17-open-parameters.md)。
